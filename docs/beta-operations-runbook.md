# VIIMsignal 클로즈드 베타 운영 Runbook

## 운영 원칙

- 베타 중 재고 이동·재주문은 자동 실행하지 않는다.
- AX 추천은 의사결정 보조이며 담당자 승인과 제약 확인을 거친다.
- 실패한 적재는 기존 정상 데이터를 대체하지 않는다.
- 회사 간 데이터, AX 대화, 감사 이력은 절대 혼합하지 않는다.
- 장애 시 새 실행보다 데이터 정확성과 복구 가능성을 우선한다.

## 배포 게이트

1. `pnpm test` 전체 통과
2. `pnpm build` 통과
3. `pnpm check:beta-public` 통과
4. 운영 관리자 화면의 준비도 100%
5. 인증 스모크 `pnpm smoke:beta` 전체 통과
6. 대표·팀 사용자별 권한 테스트 통과

## 매일 시작 점검

운영 담당자는 `VIIMsignal_Beta_Daily_Checklist.csv`에 아래를 기록한다.

1. 판매·재고 마지막 정상 반영 시각
2. 원천–운영DB 정합성
3. 데이터 소스 오류·지연 여부
4. AX 응답과 폴백 여부
5. 열린 P0와 당일 승인 마감
6. 미완료 이동·재주문·생산 업무

## 장애 등급과 대응

| 등급 | 사례 | 초기 대응 | 목표 응답 |
|---|---|---|---|
| P0 | 회사 간 데이터 노출, 승인 없는 실행, 숫자 중대 불일치 | 실행 중지, 소스 일시중지, 관리자·대표 통보 | 30분 |
| P1 | 판매·재고 적재 실패, AX·대시보드 주요 기능 장애 | 마지막 정상 데이터 유지, 오류 수집, 우회 절차 안내 | 2시간 |
| P2 | 일부 페이지 표시·필터·다운로드 문제 | 영향 기록, 다음 패치에 반영 | 1영업일 |
| P3 | 문구·사용성 개선 요청 | 피드백 로그에 등록 | 주간 리뷰 |

## 데이터 장애 처리

1. 실패한 소스를 일시중지한다.
2. 마지막 정상 동기화와 영향 기간을 기록한다.
3. 원본 파일, 오류 행, 컬럼 매핑, 중복 여부를 확인한다.
4. 수정 파일을 미리보기로 다시 검증한다.
5. 정합성 `일치` 후 적재하고 대시보드·액션을 갱신한다.
6. 감사 이력과 일일 체크리스트에 원인·조치를 남긴다.

## AX 장애 처리

- OpenAI 지연·오류 시 규칙 기반 집계 폴백이 작동하는지 확인한다.
- 원천 파일 전체나 직접 식별정보를 프롬프트에 넣지 않는다.
- AX 답변의 기준일, 필터, 집계 근거가 대시보드와 다르면 P1로 처리한다.
- API 키 오류는 Vercel 환경변수 교체 후 재배포하고 `/api/health`를 확인한다.

## 승인·실행 장애 처리

- 승인 권한이 없는 계정에서 버튼이 동작하면 P0다.
- 재주문 승인 후 생산 실행 큐가 없으면 정합성 복구 기능을 사용한다.
- 재고 이동은 출발지 안전재고, 도착지 부족량, 수량, 배차 마감을 사람이 확인한다.
- 보류·수량 변경·승인 결과와 실행 상태는 감사 이력에 남긴다.

## 주간 운영 리뷰

- 활성 사용자와 역할별 사용 빈도
- 열린 P0/P1과 평균 해결 시간
- AX 질문 수, 응답 시간, 폴백 비율
- 추천 검토·채택·보류 비율
- 재고 이동·재주문 승인 후 실제 결과
- 업로드 오류율과 데이터 반영 지연
- 다음 주 유지·수정·제외 기능

## 종료 또는 롤백

베타를 중단할 때 데이터 소스를 일시중지하고 사용자 상태를 비활성화한다. 원본·운영 데이터·AX 대화·감사 로그의 보관 또는 삭제는 회사와 합의한 정책에 따라 처리하며, 일괄 삭제 전 별도 승인을 받는다.
