# VIIMsginal 데이터·AI 비용 최적화 설계

## 1. 목표

플랫폼 크롤링, WMS, POS, 자사몰·외부 채널 데이터를 회사별로 축적하되 AX 질문마다 원천 행 전체를 AI API에 보내지 않는다. 수집 직후 정규화·집계·특징 계산을 수행하고, 화면과 AX는 이 결과를 먼저 조회한다. 언어 모델은 질문을 안전한 분석 명세로 바꾸거나 여러 지표의 의미를 해석해야 할 때만 사용한다.

## 2. 데이터 계층

1. **원천 보관**: 원본 CSV/JSON을 조직별 비공개 Storage에 저장한다. 파일 해시, 수집 배치 ID, 수집 시각, 스키마 버전을 함께 기록한다.
2. **정규화 관측값**: `market_product_observations`에 플랫폼 상품 관측값을 upsert한다. 동일 조직·플랫폼·상품·수집 시각·순위 유형은 중복 저장하지 않는다.
3. **일별 분석 마트**: `market_product_daily_metrics`, `market_brand_daily_metrics`에 상품/브랜드/플랫폼별 가격, 할인율, 순위, 평점, 리뷰, 노출 대리 지표를 계산한다.
4. **특징 저장소**: `analysis_feature_snapshots`에 예측과 추천에서 반복 사용하는 입력 특징을 버전과 데이터 워터마크와 함께 저장한다.
5. **예측 저장소**: `forecast_snapshots`에 대상, 기준일, 예측 기간, 모델 버전, 신뢰도를 저장한다. 동일 조건에서는 계산 결과를 재사용한다.
6. **가격 최적화 저장소**: `discount_recommendation_snapshots`에 상품·채널별 6개 할인 구간, 권장 할인율, 예상 기여이익, 종료 재고, 비할인 대안과 승인 상태를 저장한다.
7. **AX 응답 캐시**: `ax_query_cache`가 조직·페이지·정규화 질문·필터·최신 소스 워터마크 조합의 계획과 결과를 15분간 재사용한다. 워터마크는 서버 인스턴스에서 30초간 재사용해 반복 질문의 DB 왕복을 줄인다.

## 3. 처리 흐름

```text
크롤러/API/파일 업로드
  → 원본 파일 보관 및 검증
  → 정규화·중복 제거·격리(quarantine)
  → 일별/시간별 분석 마트 갱신
  → 특징 스냅샷 갱신
  → 규칙/통계 모델 예측 갱신
  → 할인 최적값·비할인 대안 갱신
  → 대시보드·AX 질의
```

- 수집: 플랫폼 특성에 따라 10~60분 주기, 실패 배치는 재시도한다.
- 집계: 정상 배치가 끝난 직후 증분 갱신한다. 이번 샘플은 `refresh_market_daily_analytics`가 담당한다.
- 예측: 기본은 매일 1회, 판매속도·재고·순위가 임계치 이상 변하면 추가 실행한다.
- 할인 추천: 가격·비용·재고 스냅샷이 갱신되면 `refresh_discount_recommendations`로 0·5·10·15·20·30% 시나리오를 계산한다.
- 캐시 무효화: `data_sources.last_synced_at`, 특징 갱신 시각, 예측·할인 추천 생성 시각 중 최신 값을 질문 캐시 키에 포함한다.

## 4. AX 질문 처리 원칙

1. “채널별 매출”, “브랜드 순위” 같은 표준 질문은 규칙 기반 라우터가 지표·차원·차트를 결정한다. AI 호출이 없다.
2. 화면은 RLS와 페이지 권한을 거친 집계 RPC만 호출한다. 원천 행을 브라우저나 언어 모델에 직접 전달하지 않는다.
3. “왜”, “원인”, “추천”, “예측”, “전략”, “시나리오”처럼 해석이 필요한 질문만 언어 모델로 분석 계획을 만든다.
4. 언어 모델에는 질문, 현재 페이지, 필터, 허용 지표 목록, 필요한 소규모 집계/특징만 전달한다. 전체 CSV와 개인정보는 전달하지 않는다.
5. 결과에는 `source_watermark`, 특징/모델 버전, 감지 기준을 노출해 사용자가 근거 시점을 확인할 수 있게 한다.
6. 동일 질문은 조직·권한·필터·워터마크 단위로 재사용하고 토큰 사용량과 캐시 적중률을 기록한다.
7. “최적 할인율”, “정상가 유지”, “할인 없이 소진” 질문은 언어 모델 대신 저장된 할인 추천을 조회하고, 언어 모델은 필요한 경우에만 근거를 설명한다.

## 5. 비용 절감 효과

- 원천 263만 행 대신 브랜드 일별 특징 275건 또는 화면에 필요한 상위 20~100건만 조회한다.
- 단순 조회는 SQL/RPC에서 끝나므로 AI 비용이 발생하지 않는다.
- 반복 질문은 `ax_query_cache`에서 즉시 응답하며, 재고 실행 데이터와 AX 질의는 프론트에서 병렬로 조회한다.
- AI 라우터가 4.5초 안에 응답하지 않으면 허용된 지표·차원만 사용하는 규칙 기반 라우터로 전환한다.
- 예측은 질문 때마다 재계산하지 않고 `forecast_snapshots`의 승인된 버전을 사용한다.
- 할인 추천도 질문 때마다 재계산하지 않고 `discount_recommendation_snapshots`의 최신 버전을 사용한다.
- 시스템 지시문과 JSON 스키마는 고정된 앞부분으로 유지해 공급자 측 프롬프트 캐시가 적용되기 쉬운 형태로 운영한다.

## 6. 조직·보안 경계

- 모든 관측값, 집계, 특징, 예측, 캐시는 `organization_id`로 분리한다.
- RLS와 페이지별 `view/update/approve` 권한을 동시에 적용한다.
- 외부 플랫폼 데이터에는 고객 개인정보를 넣지 않는다. 고객/배송 데이터가 필요한 분석은 별도 비식별 고객 마트에서 지역 단위로 집계한다.
- OpenAI/Claude/API 키는 서버 환경 변수에만 저장하고 브라우저 번들·DB·로그·대화 기록에 저장하지 않는다.
- AX 대화 기록은 회사·사용자·페이지 단위로 저장하되, 승인 액션은 별도 감사 로그에 기록한다.

## 7. 이번 `products.csv` 반영 상태

- 전체 2,636,573행을 스트리밍 점검했다. 플랫폼 7개에서 각 100건씩, 총 700건의 결정론적 샘플을 Supabase에 적재했다.
- 적재 후 생성 결과: 상품 일별 700건, 브랜드 일별 275건, 특징 스냅샷 275건, 집계 실행 로그 2건이다.
- 현재 파일만으로 가능한 분석: 플랫폼/브랜드/카테고리/상품별 순위, 할인율, 가격, 평점, 리뷰 수, 순위 기반 노출 대리 지표.
- `exposure_score`는 실제 노출 수가 아니라 순위로 계산한 대리 지표이므로 UI에 반드시 “순위 기반”으로 표시한다.
- 자사 상품 8개와 외부 상품의 자동 매칭 추천 40건을 생성했다. 자동 결과는 `suggested`이며 담당자가 확정하거나 제외할 수 있다.
- 최근 28일 내부 판매와 최신 재고를 사용해 자사 상품 8개의 14일 수요예측 스냅샷을 생성했다.

## 8. 다음 크롤링 스키마에 추가할 필드

- 상품 표현: `image_url`, 대표 색상, 소재, 시즌, 성별, 스타일 태그, 옵션/품절 상태
- 반응/노출: `like_count`, 실제 `impression_count`, 찜/클릭/댓글, 리뷰 증분
- 판매/재고: 공개·계약상 허용되는 범위의 판매량, 재고 여부, 판매자, 배송 리드타임
- 마케팅: 쿠폰, 프로모션명, 광고/스폰서 노출 여부, 라이브커머스 여부
- 운영 메타: `crawl_batch_id`, 수집 지역·언어·통화, HTTP 상태, 파서 버전, 재수집 여부
- 내부 연결: 자사 `product_id`/스타일 클러스터와 외부 상품의 매칭 신뢰도

플랫폼 데이터는 가능하면 공식 API·파트너 피드·계약된 데이터부터 사용하고, 크롤링은 각 서비스 약관·robots 정책·저작권·개인정보 조건을 검토한 범위에서만 운영한다.

## 9. 운영 지표

- 수집 성공률, 지연 시간, 중복률, 격리 행 수, null/형식 오류율
- 집계 처리 시간, 입력/출력 행 수, 최신 워터마크, 실패 사유
- 질문당 AI 호출률, 평균 토큰, 캐시 적중률, 질문당 비용
- 예측 오차와 모델/특징 버전별 성능, 사용자가 조정한 예측 이력

## 10. 구현 상태와 다음 순서

완료:

1. 마켓레이더의 외부 시장 일별 집계 연결
2. 내부 판매·재고와 외부 시장을 연결하는 `product_market_matches` 및 검토 상태
3. `refresh_sales_forecasts` 기반 14일 상품 수요·재주문 스냅샷
4. 마켓레이더와 AX 질문의 `query_product_intelligence` 연결
5. 특징·예측 워터마크를 포함한 AX 캐시 무효화
6. 수익성 화면의 `최적 할인 추천` 탭과 상품·채널별 시나리오 곡선
7. `refresh_discount_recommendations` 기반 권장 할인율·비할인 대안·승인 상태 저장
8. AX 할인 질문을 저장된 최적화 결과로 직접 라우팅

크롤러 전 우선순위:

1. 할인 추천과 실제 판매·기여이익 결과를 비교하는 가격 백테스트
2. 브랜드별 최대 할인율·최소 이익률·채널 동시 가격 정책 설정
3. 예측 결과와 실제 판매의 오차를 저장하는 백테스트 테이블 및 정확도 화면
4. 매칭 확정 결과를 상품기획 후보와 경쟁 비교 화면에 재사용
5. 관리자용 AI 호출률·캐시 적중률·예측 정확도 모니터링
6. 내부 데이터 동기화 완료 시 매칭·예측·할인 추천 갱신 작업 자동 실행

마지막 단계로 실제 크롤러의 Storage 업로드, 정규화 upsert, 배치 완료 이벤트를 연결한다.
