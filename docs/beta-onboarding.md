# VIIMsignal 클로즈드 베타 온보딩

## 적용 범위

첫 베타는 회사 1곳, 브랜드 1개, 사용자 3~5명으로 제한한다. 기존 `DEMO BRAND`는 제품 검증용 파일럿이며 실제 브랜드는 별도 조직과 워크스페이스로 생성한다. 회사 간 데이터·AX 대화·감사 이력은 공유하지 않는다.

## 시작 전 회사 담당자에게 받을 것

1. 회사명, 브랜드명, 운영 국가와 통화
2. 대표 승인자, 데이터 운영자, MD/재고 담당자, 조회 사용자
3. 최근 30일 판매 파일과 최신 재고 파일
4. 매장·창고 코드표, SKU 코드표
5. 판매·재고 갱신 주기와 파일 생성 담당자
6. 개인정보·원가 데이터 취급 책임자와 보관 정책

직접 식별정보인 고객명, 전화번호, 상세 주소, 이메일은 받지 않는다. 고객 분석이 필요하면 회사가 생성한 비가역 익명 토큰과 시·군·구 수준 배송지역만 사용한다.

## 계정과 권한

| 역할 | 권장 인원 | 용도 | 승인 |
|---|---:|---|---|
| 대표(owner) | 1 | 전사 조회·최종 승인·계정 관리 | 가능 |
| 전체 관리자(admin) | 1 | 데이터 연결·사용자·장애 대응 | 가능 |
| 팀 관리자(manager) | 1~2 | MD·재고·생산 업무 검토 | 담당 범위 |
| 팀 구성원(member) | 1~3 | 데이터 조회·실행 준비 | 기본 제한 |
| 조회 전용(viewer) | 선택 | 경영·재무 공유 | 불가 |

`VIIMsignal_Beta_User_Roster.csv`에서 이메일과 이름을 회사 정보로 바꾼 뒤 사용자·권한의 일괄 등록에 업로드한다. 대표 계정은 중복 초대하지 않는다.

## 데이터 연결 순서

1. `VIIMsignal_Beta_Field_Mapping.csv`에 회사 원천 컬럼과 담당자를 기록한다.
2. 판매 파일을 `auto`로 미리보기하고 `sales_order` 추천과 필수 컬럼을 확인한다.
3. 오류 행을 수정한 뒤 확정 적재한다.
4. 재고 파일을 같은 방식으로 `inventory_snapshot`으로 적재한다.
5. 데이터 연결에서 두 파일의 성공/오류 행, 정합성 `일치`, 마지막 반영 시간을 확인한다.
6. 사용자·권한에서 회사 컬럼 매핑 재사용과 전체 준비도 100%를 확인한다.

WMS API가 없으면 일별 CSV/XLSX 업로드를 기본 운영 경로로 사용한다. API가 준비되면 표준 엔티티를 바꾸지 않고 입력 방식만 커넥터로 교체한다.

## 숫자 대조

회사 원천 파일과 아래 5개 수치를 반드시 대조한다.

- 기간 내 순매출 합계
- 판매수량 합계
- 주문 수
- 최신 가용재고 합계
- SKU·매장 수

차이가 있으면 베타를 시작하지 않고 데이터 연결의 정합성 결과와 오류 행부터 수정한다.

## 온보딩 완료 기준

- 운영 준비도 100%, 차단 항목 0개
- 대표·관리자·팀 사용자의 접근 범위 확인
- 판매·재고 파일 재업로드 시 저장된 매핑 재사용
- AX 숫자와 동일 필터 대시보드 숫자 일치
- 승인 후 재고 또는 생산 실행 업무와 감사 이력 생성
